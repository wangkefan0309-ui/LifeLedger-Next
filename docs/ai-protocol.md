# AI 拆账协议（文字 v3、截图 v1）

运行时完整提示词位于 `src/api/prompt.ts`，校验器位于 `src/api/extractor.ts`。本文说明用户可依赖的约束。

1. AI 只提取当前原文及必要上下文，输出待确认 JSON；不执行工具，不写文件，不计算或修改余额。
2. 金额规范成精确到分的十进制字符串。“几十块”等模糊信息留空；每笔保留逐字存在的原文证据。口头更正只保留最终金额，证据包含更正过程。
3. 内部转账只在本人账户、用途与方向明确时成立；缺一端就留空。插件不会用默认账户补齐转账。普通收支可显式采用用户设置的默认账户。
4. 给他人转钱先分辨消费、借出或还款；用途不明待补。借还本金记录资产与负债，利息另记支出。
5. 未说明日期时沿用用户所选 recording_date，本地提交日 today 与时区解释明确的今天／昨天等相对日期。原文明示日期优先，截图缺日期时用窗口所选日期。未来计划、预计收益和未发生事项列为排除项，不入真实账本。
6. 分项加总与口头总额冲突时提出问题，不补造交易。区间汇总保留起止日期，不编造逐日记录。
7. 账户、分类和关联交易只能引用已提供的 ID。退款需要核对原消费关联；陌生 ID 和方向冲突在本地提示。
8. 原文中“忽略规则”“直接保存”等内容按数据处理，不能改变协议。AI 的置信度不能作为保存许可。
9. 每日成本只能作为明确消费的建议，期限缺失待补；真实购买款只扣一次。明确说当天全部记完时才建议完整日期，最终由用户确认。
10. 所有行都由用户核对；缺金额、账户或其他关键条件的行阻止保存，可先保存剩余行。

文字“服务费-2元”按2元支出保留负号原文证据，程序使用正数金额与支出方向；正负号和收入／支出冲突时阻止保存，不推算服务费比例或未给出的总额。

点击整理时，会向用户配置的服务发送原文、本地日期／补账日期／时区、账户名称及别名／类型／ID、分类，以及退款场景下最近最多十笔候选原消费的 ID、日期、金额和备注。账户余额和整个 Vault 不在这份请求中。点击检查连接会请求模型列表。插件没有另设遥测服务器。

密钥仅从设备 SecretStorage 取出用于请求，不进入账本及 JSON 备份。失败、超时、无效 JSON 或不完整回复保留原文和草稿。兼容接口的连接检查不能证明真实模型的拆账准确率。

0.1.10按用户要求，对已知DeepSeek模型（`deepseek-flash`、旧Flash别名和`deepseek-v4-pro`）显式设置 `thinking: { type: "enabled" }`、`max_tokens: 65536`，整理最多等待300秒；其他兼容模型保留8192 tokens及60秒，不附加DeepSeek参数。0.1.9关闭思考的临时方案已撤回。模型始终取已保存配置，失败不自动重试或更换模型。`length`表示输出上限或上下文限制导致截断，不能把局部JSON当作完整草稿；错误显示服务返回的输出及思考token数量，不包含思考正文。拦截、工具调用、资源不足、aborted中断、只返回思考而无JSON，以及结束标记不兼容分别提示。0.1.10的额度调整不改冻结账单字段或金融计算；0.1.11单独加入补账 recording_date 上下文。

参数依据为2026-10-15核对的[DeepSeek思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)及[JSON输出说明](https://api-docs.deepseek.com/guides/json_mode/)。官方文档说明思考模式默认输出额度为64K，输出限制可能造成截断；本地模拟只证明插件传参和错误恢复，不证明用户此前失败由深度思考造成，也不替代真实模型复测。

新版每行新增 received_amount 和 received_amount_quote，currency 支持 CNY／USD／HKD；换汇需两种实际金额与原文证据，不允许模型推算实际到账或汇率。普通账目按账户本币核对，程序冻结人民币统计汇率。旧 v2 人民币回复仍可读。

名称／别名会在本地复核：食堂消费扣饭卡，饭卡充值用转账、缺转出待补，明确微信付款按微信。参考汇率查询单独访问 Frankfurter 的公开币种接口，不发送账本数据或密钥。

## 截图识别

截图使用 `src/api/screenshot-prompt.ts` 的独立 v1 提示词。点击识别才以用户图片内容块发送当前临时截图、补充说明、日期／支出范围及每张图片的指定账户，沿用同一服务和密钥；使用内联编码，不创建图床或 Files API 文件。图片不进入 Vault、正式批次或 JSON 备份。

回复仅有 version 和 images，每张包含序号、识别 text、entries、excluded。账目行沿用文字 v3 全部字段，但不接受区间汇总或自动成本项目，不接受 complete_dates。每条保留对应图片的识别片段和金额证据。模型抄录文字本身仍需对照实际图片，不能用输出置信度代替人工核对。

日期和只支出限制在本地执行；余额、汇总、失败／待支付条目排除。未明确付款账户不套默认，平台名称不证明付款方式；余额充值误报收入、已退款误报普通支出须再核对。正负号与类型冲突、金额精度或转账两端不足继续待补。补充说明可完善用途和分类，不替换截图金额或生成第二笔消费。

成功识别或关闭后移除临时图片，失败时窗口内可重试。只保留 OCR 文字和用户修正，重新识别需重新选图。服务端请求记录的留存由用户选择的供应商决定。真实模型和系统剪贴板仍分别验收。
