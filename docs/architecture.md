# 理念、计算与存储

## 从钱到时间

LifeLedger 把日常流水、多账户资产与生活成本放在同一处。记录支出后，可以观察现有资金按当前生活成本能支持多久；积累收入或调整消费后，再观察自由天数的变化。人生亮格提供逐日的视觉反馈，让保存一笔账有可见的结果。

自由天数是当前资金和已记录生活成本的比值，随账户设置、余额和完整日均变化。它不预测未来收入、投资收益、通胀或意外费用，也不把未发生的收益记作现金。首页标语可由用户设置，默认“把账记清楚，把日子过明白”；可支撑天数来自具体数据。

## 计算口径

```text
总资产 = 所有资产账户按当前参考汇率折为人民币后的余额合计
净资产 = 总资产 − 负债余额合计
可用资金 = Σ（资产账户余额 × 纳入比例）− 负债 − 单独预留资金
自由天数 = 向下取整（max(0, 可用资金) ÷ 长期日均生活成本）
```

金额以本币整数分保存和计算，比例以万分比保存。账户显示本币；总资产、负债、可用资金及收支合计统一展示人民币。资金预留只扣一次；已通过余额或纳入比例排除的资金不再次预留。没有正的生活成本基线时，自由天数显示待建立基线；设置中的暂估日均会明确标注。

生活成本来自从观察起点开始的连续完整日期。未确认的日期截断完整区间；没有流水且未确认的日子不算零。明确确认零收支后才加入完整日均。分类可配置是否属于生活成本。被动收入按已到账收入标记统计，不自动抵扣支出分母。

内部转账改变两端余额，不计收入或支出。同币种、两端纳入比例相同时，可用资金保持不变；比例不同时，可用范围随转账变化。跨币种换汇按实际扣款和到账改变两端余额，参考折算的净资产可能因成交价和参考价的差别变化。借入同步增加现金和负债；还本金同步减少现金和负债，利息另记支出。借出与收回本金使用普通资产账户和用户自建的应收款账户。

余额以期初生效日为锚点，之前的历史流水不再改变该锚点之后的现金。退款按到账日改变余额；只有原消费已进入同一观察区间时，退款才抵减该区间的生活成本。设备或订阅按真实日历分摊，不作为第二次现金扣款。

## 模块

```text
src/core/       领域类型、整数金额、交易规则、完整度与计算
src/storage/    Vault 文件、校验、批次、更正、撤销、备份恢复
src/api/        冻结提示词、API 请求、JSON 草稿与本地校验
src/ui/         五页、核对表单、图表、人生格和资源清理
tests/          虚拟样本的核心与存储测试
scripts/        构建、打包和隔离 Obsidian 检查
```

AI 层只能生成草稿。确认后的计算、校验和写入全部由插件完成。保存首页与外观会更新配置中的标语和主题偏好；系统深浅模式变化只更换 CSS 变量、SVG 配色和 Canvas 实例色板，不写配置或交易数据。视图销毁时断开尺寸及主题观察器和系统偏好监听，取消 RAF、等待及动画，关闭音频。

## 本地文件

默认账本目录为 Vault 内的 `LifeLedger/`：

```text
LifeLedger/
  配置.md
  账本/YYYY-MM/<批次ID>.md
  草稿/<草稿ID>.md
```

`lifeledger-json` 块是计算依据，块外可以保留笔记。配置保存账户、分类和展示设置；草稿保存原文与修正；正式账本采用带校验和及父引用的追加批次。更正、删除和撤销追加事件，保留历史。

配置的 `accounts` 数组保存用户选择的账户顺序，首页资产卡和账户明细沿用同一顺序。排序只重排数组；修改账户在原位置替换，新账户追加末尾，ID及历史流水引用保留。排序保存使用配置指纹防止旧窗口覆盖新配置，备份恢复直接保留数组顺序。

无效、残缺或冲突批次保留并提示，不强行纳入统计。正式账本损坏时暂停新账保存，草稿问题单独处理。完整 JSON 备份包含配置、批次和草稿，恢复目标必须为空；备份不包含密钥。

设备 API 地址、模型和账本路径由 Obsidian 的插件配置保存；密钥使用 Obsidian SecretStorage。文件读写使用 Vault API，读改写使用 `Vault.process()`；路径经过规范化及边界检查。该机制处理本机读写，不提供跨设备事务或复杂并发同步。

`LifeLedger` 是默认数据目录名，可换成当前 Vault 内的普通嵌套路径。Repository 按已配置路径读取固定的 `配置.md`、`账本/` 和 `草稿/`；文件夹改名事件不会更新设备设置中的路径。`changeRoot()` 先校验并读取目标，再保存设备路径、切换仓库并重建视图，只切换读取位置，不搬迁文件。移动账本需停用插件、整体移动数据目录并重新指定路径，步骤见 [使用指南](guide.md)。

## 按日对账与补账日期

草稿可选字段 `recordingDate` 保存用户所选补账日；旧草稿缺失时回退提交日。提交日仍用于相对日期，明确原文日期优先。编辑表单重建时保留原生弹窗及Obsidian祖先滚动位置，恢复焦点使用preventScroll。

`core/reconciliation.ts` 按本币整数分计算截止日日终余额和区间解释，筛查草稿及最多40项差额候选；双笔组合最多检查最近200条。对照明细先完成整份账单的精确匹配，再列同描述金额差异，逐笔消费匹配额度，不合并真实同额交易。

对照编辑器是临时状态，不自动保存草稿或流水。截图成功／关闭即释放，只有用户选择的漏记项进入正常未核对草稿。确认记录写配置可选 `reconciliations`，包含账户、起止日、实际分值、核对时间、balance／statement范围及相关流水SHA-256指纹，备份自然携带；相关历史或期初改变后失效。确认不写交易及全天完整度。旧配置无需迁移，保存仍检查配置冲突。

## 当前实现边界

当前自由天数历史曲线按现有配置回算，没有历史配置快照。未提供周／月聚合折线、跨会话逐笔回放、历史账单导入向导、自动行情、其他币种、跨币种借还本金、完整负债分期、预算和收益预测。手机录入、内置录音、自动保存 AI 结果、消费模拟及自动 Markdown 复盘未加入。

AI 研发检查使用虚拟数据和模拟 API，真实 AI API、Typeless、人工音效和长期日常使用分别验收，不能由模拟结果推定。公共参考汇率已单独通过插件真实请求路径验证。

## 多币种与冻结历史汇率

账户原始整数分按各自本币存储，旧记录缺币种时为人民币。配置缓存 CNY／USD／HKD 的参考汇率（八位定点整数）、来源、报价日期和获取时间；账户卡片显示约合值，当前资产和自由计算按人民币折算。取整使用 BigInt 中间计算，不用浮点数直接保存金额。

交易 valuation 保存币种及当时人民币汇率；历史收支采用该快照。exchange 保存转入账户实际到账与目标币种快照，一条内部转账同时影响两端本币余额。更正／删除／撤销保持追加保存，所有历史引用账户的币种固定。外币退款按原消费快照抵生活成本，避免把汇率差误作负成本。

AI v3 增加到账金额及证据，不产生汇率。账户名称、唯一别名和明确付款词在本地复核，充值识别为转账、缺来源待补。原文涉及其他账户但片段漏掉证据时，不静默使用默认钱包。v2 人民币格式保持兼容。

## 临时截图与文字草稿

图片对象属于录入窗口的临时状态，成功识别或窗口销毁时清除；不通过 Vault API 写附件，不进入账本、设备配置或备份。图片在用户主动识别时以内联内容块发送到现有 API。

截图 v1 回复拆成图片识别文字及 v3 账目行。Draft 的 inputMode、imageEvidence（ID 与文字）和行 imageId 保留证据关系；正式交易 originalText 保留补充说明及识别文字，人工修改进入更正记录。来源片段和金额正负号／单位在本地校验，保存仍使用原有整数分、批次、核对、撤销和恢复路径。截图不自动设置完整日期。
